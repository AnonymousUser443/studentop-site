# 备选通道：用普通 TCP 隧道先让公网能访问（立即可用）

> 背景：浮居的**建站节点（会员-建站1号）已宕机 ≥24h**，官方状态页可用率 0%；而其余 7 个节点（北京1/2、浙江1/2、四川1、湖南1、广东1）全部 UP。
> HTTP/HTTPS 建站隧道**只能**用【建站】节点，所以想"今天就通"，可以改用 **TCP 隧道**——TCP 隧道在任意节点都能用。

## 一、和建站隧道的区别

| | 建站隧道（type=https） | TCP 隧道（type=tcp） |
| --- | --- | --- |
| 可用节点 | 只有【建站1号】（当前 DOWN） | 所有在线节点（北京/浙江/四川/湖南/广东） |
| 访问地址 | https://studentop.cn（默认 443，免端口） | https://studentop.cn:远程端口（10000–19999，**必须带端口**） |
| 域名分流 | 节点按 SNI/Host 路由 | 不解析域名，纯端口转发；域名只用来解析到节点 IP |
| TLS 证书 | 装在树莓派本地 443（SNI 透传） | **同样**装在树莓派本地 443 |
| 上网体验 | 无端口、最标准 | 有小锁但地址带端口；个人主页完全可用 |

TCP 隧道的链路：

```text
浏览器 https://studentop.cn:14355
  → DNS：studentop.cn → 节点 IP（A 记录 / CNAME 到节点域名）
  → 浮居节点 :14355（纯 TCP 转发）
  → frpc（树莓派）→ 127.0.0.1:443（nginx，证书在 Pi 上）
```

## 二、面板操作（5 分钟）

1. 登录浮居面板 → 新建映射/隧道：
   - **节点**：选状态在线的（推荐「浙江1号」或「北京1号」；带宽 100M 用北京/浙江1，1G 用浙江2/湖南1/广东1）
   - **类型**：`TCP`
   - **本地 IP**：`127.0.0.1`
   - **本地端口**：`443`
   - **远程端口**：10000–19999 之间任选一个（例如 `14355`），不要和别人冲突
   - （TCP 隧道不需要填自定义域名）
2. 保存后，在该隧道详情里点「配置文件」，把整段配置复制出来（包含 `server_addr`、`server_port`、`user`、`token` 以及 `[隧道名]` 段）。
3. 把配置发给我即可（不放心可把 token 打码，我只需要结构；但若要我直接部署就**别打码**）。

面板生成出来的形如（示意，以面板为准）：

```ini
[common]
server_addr=<节点地址>
server_port=<节点端口>
user=<用户标识>

[win11-home]

local_port = 443
remote_port = 14355
```

## 五、注意事项

- 浮居文档写明「建站只能用香港/海外节点」；境内节点跑 TCP 承载网站**技术上可行**，但若被判定为建站/触发备案要求，可能被限速或要求整改。个人主页流量很小，风险低。
- TCP 隧道的远程端口范围是 **10000–19999**（这是限制远程端口，不是本地端口）。
- 想免端口（https://studentop.cn）只有三条路：①等建站1号恢复 / 让浮居开香港-海外建站节点；②有自己的香港 VPS，用 frps 自建；③把域名 NS 迁到 Cloudflare 用 Cloudflare Tunnel（免费、免端口、自动证书）。
