# 在线校园内容工坊

入口：[线上工坊](https://liyun.studentop.cn:14355/studio/)。填写协作昵称和团队协作口令加入。编辑会话与玩家账户分开。

本地可双击应用目录的 `start-studio.cmd`，或运行 `npm run studio`；地址为 `http://127.0.0.1:5174/studio/`。本地草稿与服务器草稿属于不同数据库，团队正式协作请使用同一个线上入口。旧版严格8点工具仍可在开发环境用 `/?tool=calibration&legacy=1` 访问；新版不再受8点限制。

## 编辑一站

1. 左侧选择景点，切到“介绍与照片”修改名称、介绍、寄语和图标；每站最多6张照片，上传时会转换为WebP并缩至最长1800像素。初始插画标注为概念占位，可以替换。
2. “分区边界”可重新描绘、拖动顶点、输入UV、插入中点和删除顶点。至少3点后点击“一键闭合”、点击首点或按Enter；无需重复第一点。整理产生的多块区域和内孔可以在轮廓下拉框切换编辑。
3. “打卡范围”可拖中心与金色半径手柄，也可输入UV、米制半径（5–200米）或手填现场WGS84。移动UV会解除旧手填坐标绑定。范围先以WGS84采样后投影，不等于实测定位精度；不要直接填火星或百度坐标。

“新增景点”后点击校区内位置即可增加一站；填写介绍后再发布。“删除这一景点与分区”有确认提示，至少保留一站。删除只改团队草稿，旧版线上内容在下一次明确发布前保留；历史打卡ID与已发布图片保留以兼容存档和缓存。

鼠标中键或拖动空白区域平移，滚轮/双指缩放。中键在描绘模式下也只移动镜头。每人的镜头、当前选择和解锁预览独立；内容改动自动同步。

## 重叠、空隙与解锁预览

“分区边界”和“打卡范围”可同时显示。红色为重叠，斜纹为尚未覆盖的校区区域。画布底部显示实时覆盖率。

“修复重叠 / 补齐空隙”保留手绘区域的独占部分，把重叠及空白按当前打卡中心分配。若中心已经移到不属于自己的独占区域，可先调整边界，或在“更多 → 按打卡点重新分区”明确替换全部分区。整理会作为一批团队操作自动同步，可撤销；两个中心重合时应先移开，不能把它们当作可独立划分的点。

“解锁预览”中点击景点可切换解锁，或选择“全部解锁”。覆盖检查必须通过，且各打卡中心位于对应分区及校区范围内，才能发布。因此“全部解锁”对应的是团队划定的校区面积，不包含该边界之外的行政区域；边界和位置仍需队员人工核对。

## 自动同步与发布

改动约每300ms批量保存，顶部显示保存中、已同步、重连或冲突。服务器使用SQLite保存草稿和版本，并通过SSE向成员推送更新。不同字段可以合并，同一字段的过期修改会要求选择保留服务器内容或自己的改动；不会整份静默覆盖。

断网时未同步操作保留在当前标签页，恢复后自动重试；关闭未保存页面会提示。可随时导出JSON备份。多人同时编辑时，“撤销”仅撤销自己的最近一批操作；若对应字段已被别人更新，不能用撤销覆盖对方。

点击顶部“预览草稿”，确认当前版本，再点击“发布到游戏”并勾选核对声明。新成员改动导致版本变化后，需要重新预览。发布会保留版本记录，将当前快照提供给玩家；玩家刷新后读取新景点、图文、分区和打卡范围。游戏内预览使用 `?contentPreview=版本号`，与个人存档、账户同步隔离。

JSON导入支持新版备份及旧版审查稿，并作为一批团队改动同步。照片只能引用当前服务器已上传的文件或原有占位图，跨服务器迁移时应重新上传实际照片。

## 服务器与验收交接

协作服务 `liyun-author.service` 只绑定 `127.0.0.1:8790`，由同域nginx提供 `/studio/`、`/api/editor/` 和 `/api/content/`。草稿数据库、会话和照片位于私有目录 `/var/lib/liyun-author`；只有已发布的公开配置导出到 `/var/lib/liyun-content/published.json` 供玩家账号白名单读取。协作口令不进入Git、前端或发布日志。

本轮多人端验收已按用户要求交由团队手动完成。后端与几何单测、类型和构建用于发布门禁；此前隔离浏览器的12个局部通过项只作为局部证据，不表示多人端完整验收。剩余手工操作可按新增/删除景点、两人改不同字段/同字段、照片、断网恢复、中键拖动和预览后发布依次核对。

字体使用Noto Serif SC（OFL），许可随工坊产物的 `assets/NotoSerifSC-OFL.txt` 一并提供。几何布尔运算使用[polygon-clipping官方实现](https://github.com/mfogel/polygon-clipping)，支持多块区域和内孔。
