# 桌面交互、私密锁屏与原版开场修订 · 2026-10-28

> 本轮只做本地开发与验收；不提交、不推送、不部署。此文更新 [上一轮验收](<UPGRADE-ACCEPTANCE.md>) 的窗口边界、锁屏授权和开场入口约定。

## 本轮目标与边界

- 桌面普通窗口允许部分移出屏幕；只限制到仍有可抓标题栏，不再要求整窗可见。提供任务栏右键“移回屏幕”。窄屏仍以可用性优先。
- 校园纸境入场和原版“原神启动”分别保留，开发路径分别为 <http://127.0.0.1:8081/> 与 <http://127.0.0.1:8081/legacy.html>，原版生产产物独立，不注入校园轻量包。
- 首次访问先经历可跳过的 BIOS 风格网页演示，再显示用户给定的薄荷绿窗格 LOGO。后续访问不反复等待。尊重减少动态偏好，动画不授予登录权。
- 锁屏问题公开显示；答案由私密服务端校验，公开前端没有答案、可离线比对的答案哈希或静态放行代码。
- 三次错误后，同一来源地址禁用五分钟；服务器记录剩余次数与到期时间。刷新、更换浏览器存储、换匿名cookie或重启服务不重置有效禁用期。超过五分钟后自动恢复三次机会，不反复延长处罚。

## 私密校验与维护

本地启动器已集成 [认证模块](<../tools/desktop-auth.mjs>)，默认将 verifier 与限流状态保存在**仓库外的当前用户数据目录**。Windows 为 LOCALAPPDATA/AidenDesktop/工作区指纹；Linux 为用户本地数据目录。可以使用 DESKTOP_AUTH_CONFIG 显式指定仓库外稳定路径。不要把该目录放进站点、Git、网盘公开分享或构建产物。

持久化内容仅包含随机salt、scrypt verifier、随机地址摘要密钥和不可逆地址索引/计数/时间；不保存输入答案、真实姓名明文、原始客户端地址。会话保存在单个服务进程内，浏览器收到 HttpOnly、SameSite=Strict 的随机会话cookie；正式HTTPS服务还设置Secure。会话上限八小时，重启服务使已登录会话失效，未到期限流状态仍保留。

首次配置或更换答案使用 [私密配置工具](<../tools/configure-desktop-auth.mjs>)：

~~~powershell
# 在自己的交互终端输入；答案不在命令行、不回显、不写入仓库。
node tools/configure-desktop-auth.mjs
# 有意更换答案时：
node tools/configure-desktop-auth.mjs --replace
~~~

不建议将答案放在环境变量、命令行参数或示例脚本中。非交互工具可用 --stdin，但应避免shell历史/转录、CI日志和抓包保存真实输入。配置后重启本人的认证服务。本次已经完成本机配置，不需要重复配置。

### 同源接口

- GET /__desktop/auth：状态、CSRF token、剩余次数与服务器时间，无答案/校验器/客户端地址。
- POST /__desktop/auth：JSON answer，严格Origin与 X-Desktop-CSRF，最多1024字节；正确200、错误401、第三次及冷却期429。
- DELETE /__desktop/auth：校验Origin/CSRF后废除当前会话。
- 所有状态不缓存；未配置、私密状态损坏或持久化失败时503并**保持锁屏**，不会降级成点击即进。
- 页面主动锁定立即使桌面inert，并串行撤销会话；失败时保留拒绝自动恢复标记，刷新先重试撤销。URL skipLock、旧sessionStorage标记、动画跳过均不再授权。

### 正式发布前的新增条件（本轮未执行）

主页前端仍是原生无打包框架，但锁屏不再能靠纯静态托管独立运行。nginx静态站点必须将 /__desktop/auth **同源**反向代理到 [认证伴随服务](<../tools/serve-desktop-auth.mjs>)：

- 只启动一个认证进程，使用稳定的私密配置/状态路径；不支持多个进程共享JSON状态文件。
- 设置 DESKTOP_AUTH_ORIGIN 为精确HTTPS主页origin（不带末尾斜杠），DESKTOP_AUTH_TRUST_PROXY 为实际回环代理IP清单。
- 服务只绑定127.0.0.1:8900（可显式改端口）；代理必须覆盖写入真实来源的 X-Real-IP 和原始Host，不能透传用户自报地址；不要相信任意 X-Forwarded-For。
- Node>=22.12；私密目录只有服务账户可读写，禁止目录列表、源码映射及私密配置的HTTP访问；禁止记录认证请求正文。
- 不将认证接口缓存，不添加通配CORS；限制请求体，HTTPS/防刷策略由站点部署者保持。
- 原版开场资源与第三方依赖的再分发授权另行核对，详见 [原版恢复说明](<legacy-opening.md>)；本地恢复不等于授权公开分发。

**安全定位：**这是访客问答门禁，不是保护高价值秘密的完整身份系统。姓名类知识题可被认识站主的人猜中，IP限流可由更换网络绕开，也可能让同一校园/NAT网络的访客共享次数。公开前端和公开项目索引仍可读取；不得把敏感文件仅藏在窗口或JavaScript里。若要保护私人内容，应由服务端逐请求鉴权并采用真正账户认证。

### 缓存专项

旧的同名资源7天/30天缓存已从源配置修正，正式发布改用 [内容版本构建](<../tools/build-site.mjs>)。新版HTML、版本元数据再验证；仅内容指纹资源长期immutable缓存。发现新版只提示“立即更新/稍后”，不强刷，不清存储；便笺未保存则允许取消。实现、旧客户端一次迁移与部署配置应用步骤见 [缓存更新说明](<CACHE-UPDATES.md>)。

所有生产配置仅修改仓库模板，没有连接树莓派、reload nginx、安装Git钩子或触发workflow。线上缓存修复需要所有者在下一次授权发布时应用这些配置与版本产物；没有声称远程已生效。
