# 定位新鲜度修正 · 2026-11-10

## 问题与行为

收到的设备定位时间戳可能固定为 `10000`、`40000`，也可能使用相对时钟、倒退或返回无效值。不能靠识别品牌、特殊数字或时间戳量级来决定定位是否过期。

所有设备现在统一按**本页面收到定位回调后的经过时间**判断新鲜度：回调入口记录 `performance.now()` 为 `receivedAt`，超过 15 秒没有新的有效回调则过期。页面内定位数据不再保留或读取 `GeolocationPosition.timestamp`，也不再用它过滤回调顺序。

定位状态定时检查、打卡按钮和实际写入探索进度前的复查共用 `isReadingFresh()`，调用链统一使用同一个单调时钟。系统日期或时间调整不参与这项判定。

仍然使用 `enableHighAccuracy: true`、`maximumAge: 0`、15 秒请求超时；经纬度和精度检查、范围打卡、旧 watch 的 generation 拦截、后台暂停和隐私存档规则继续生效。新鲜度表示最近收到了有效回调，不能在不信任设备时间戳的同时推断设备内部实际测量的时刻。

## 修改位置

- `apps/liyun-explorer/src/location/geolocation.ts`：接收时刻、新鲜度函数和 watch 生命周期。
- `apps/liyun-explorer/src/location/checkIn.ts`：按钮与打卡校验使用同一新鲜度函数。
- `apps/liyun-explorer/src/state.ts`、`src/app/discovery.ts`：真正提交进度前也使用单调时钟，避免混入 `Date.now()`。
- 定位测试夹具默认使用设备时间戳 `10000`；原浏览器测试脚本的模拟时钟同步改为覆盖单调时钟。
