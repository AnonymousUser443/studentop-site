## 1. 覆盖范围与隔离方法

每区选择三个不同的内部 UV 点，共 **24 个点**。每点经一般多边形包含校验，确认只属于预期分区；全部坐标见 JSON 和 [几何示意图](repaired/geometry.svg)。

浏览器临时隐藏 HUD、地图标记、装饰边框和环境雾等覆盖层，使像素测试单独观察真实地图底图与真实 `RegionVeil`。高档、`reduceFlash: true`、固定时间 1000ms、相机及几何保持一致。所有隐藏和底图背景替换都仅发生在该临时浏览器档案内，没有写源 CSS 或配置。

在每区同一相机下记录：

1. 实际底图 + 锁定遮罩。
2. 隐藏底图图像、用纯黑 / 纯白背景分别照明，遮罩仍锁定。
3. 仅解锁当前区，用同样黑 / 白背景证明该点确实能响应底图变化。
4. 恢复实际底图，比较仅当前区解锁与全部遮罩卸载后的基准。

内部点取 5×5 像素均值。不能仅凭“遮罩颜色和底图不同”认定不透明；黑 / 白底不变性配合已解锁响应控制，才能排除透明雾和被 HUD 遮住等假象。

## 3. 几何、重叠与边界

当前 8 个分区均是有效凸多边形，一般多边形验证也通过。静态检查在确认凸性后，使用凸多边形裁剪计算全部 **28 对**的交面积；均小于 `1e-10 UV²`，最大数值残差约 `1.4e-17`。分区总面积和独立外边界面积都为 `0.44225000000000003 UV²`；分区都包含于外边界内。这一当前构型没有有限面积的交叠或缺口。

几何存在 **13 段共享边界、5 段游戏外边界**，全部列于 [repaired/geometry.json](repaired/geometry.json)。共享线上的点会按几何包含规则同时属于两区，这是边界归属，不是有限面积重叠。另用交面积 `0.09 UV²` 的合成正控制证明交面积检测能识别真实重叠。当前生产内容没有有限面积交叠，不能将本批声明为任意重叠多边形布局的完整渲染验收。

每条边界取中点和法线两侧各 4 CSS px 的点。共享边界特意将相机设到半像素位置，中心读取单像素，避免仅测试整数坐标时漏掉抗锯齿接缝。

第一轮：全部 13 条共享线的中心像素会随黑 / 白底改变，最大通道差 **64–77 / 255**；两侧内部点的差均为 0。示例 [原黑底](boundary-0-black.png) / [原白底](boundary-0-white.png) 可见细缝。几何没有缝隙，问题来自多个独立 SVG 片段的边缘覆盖叠加。

修复采用单个合并的、同向 `nonzero` 纸底填充，表示当前仍锁定分区的联合区域；不扩展多边形，不用加粗边线侵占邻区。重新验证：

- 全部 13 条共享边界中心及两侧的黑 / 白底差均为 **0**。示例 [修复后黑底](repaired/boundary-0-black.png) / [修复后白底](repaired/boundary-0-white.png)。
- 每对相邻区都完成 A 解锁、A/B 双解锁；双解锁后的接缝中心及两侧三点与全部无遮罩基准一致。
- 竖向“文萃 / 北湖”和横向“文博 / 塔”额外做重锁循环。重锁 A 后，A 侧仍不透明、B 侧仍对底图全响应；再解锁后没有纸底残留。
- 五条外边界的内部侧点均不透明、外部侧点均保持无遮挡。游戏外边界本身允许抗锯齿混合；单侧锁定 / 单侧开放时的共享边界中心也包含两侧覆盖，不将其强制判作完全不透明。侧点距离和测量数值完整保留。

## 4. 实际平移、缩放和几何保持

三个状态分别为带小数的初始相机、真实 CDP 鼠标拖动、真实滚轮缩放。鼠标改变相机位置，滚轮提高缩放并保持鼠标锚点 UV。每个状态的 8 条 clip path 都与内容中的原 UV 路径一致。

初始 / 平移的 CSS 与 SVG 投影差为 0。滚轮后 `computedStyle.transform` 的字符串精度有限，序列化矩阵投影所有分区顶点的最大差约 **0.001875 CSS px**；用真实 `getBoundingClientRect` 恢复地图变换与 SVG CTM 比较，最大差为 **0.000188 CSS px**。判据为投影误差小于 `0.01 CSS px`，没有将约 0.0004px 的 CSS 字符串截断误判为地图错位。原始相机、两种矩阵和误差都在 JSON。

## 5. 真正的 SVG 云纹 / ImageGen 纹理对比

新增备用路线是实际 `RegionVeil` 内的 SVG pattern：Bezier 云团、纹线和纸 / 玉色令牌。高档每区一个 `data-testid=region-procedural-cloud` 路径和一个 pattern，共 8 个，位于对应 ImageGen image 之前。

- [ImageGen 纹理优先](repaired/cloud-with-imagegen-texture.png)：高档 8 张 image，实际 opacity `.98`，SVG 备用层保留在下方。
- [SVG 程序云纹备用](repaired/cloud-svg-fallback.png)：同一相机、同一高档、同一不透明纸底和环境 p5 雾，只临时隐藏这 8 张 image；8 条真实 SVG 路径仍可见。
- 低档实际没有这 8 条 SVG 云纹路径，也没有 bitmap image，保留纯纸路线。

本轮路线选择为：正常高 / 极致使用 ImageGen 纹理，获得较自然的云海细节；图片不可用时 SVG 图形提供稳定可读的程序备用层；低档维持纯纸降低成本。A/B 是单相机固定时间的真实渲染观感比较，不是每种硬件的性能比较，也没有用 p5 环境雾冒充独立的 SVG 云纹实现。完整动态墨散与帧率证据仍需结合主 `world-cinematic/final/results.json` 和单独 PoC 录屏。

## 证据边界

本批确认的是 8 区各 3 个内部点、当前 13 条共享边中点、5 条外边中点、两条代表边重锁循环，以及三个真实相机状态。没有穷举所有边界像素、所有多区交点、任意凹多边形重叠布局、所有相机位置、手机真机或现场 GPS。推荐分区仍需要团队现场确认；本批不改变它们的推荐状态。
